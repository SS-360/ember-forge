# Ember Forge rename and compatibility

26 October 2026. The project now uses **Ember Forge**, with the tagline **Turn repeated work into reusable skills.**

## Current names

- App header, browser title, metadata, documentation and generated instructions: Ember Forge.
- Workspace packages: `@emberforge/*`; repository package: `ember-forge`.
- Brand assets: `ember-forge.svg`, `ember-forge-symbol.svg`, `ember-forge-lockup.svg`.
- The original pocket-and-flame SVG artwork is retained; only its name and wordmark text change to Ember Forge.
- Newly exported runtime: `runtime/emberforge-runtime.mjs`.
- Newly generated format identifiers: `emberforge.*`.
- Preferred local environment variables: `EMBERFORGE_API_PORT` and `EMBERFORGE_CODEX_BINARY`.

## Existing data

Existing artifacts are not rewritten to look as though they were generated by the renamed app. Their content hashes, verification reports, provenance and trust-ledger history remain meaningful.

- Contract validators accept the original `pocketforge.*` identifiers alongside the current `emberforge.*` identifiers, preserving values rather than transforming hash-bound input.
- The supplied seed JSON and historical frozen evaluation JSON retain their original identifiers and recorded hashes.
- Existing `artifacts/pocketforge.sqlite` history is reused when present. A workspace without that database creates `artifacts/emberforge.sqlite`.
- Original `POCKETFORGE_API_PORT` and `POCKETFORGE_CODEX_BINARY` variables remain fallbacks; their Ember Forge equivalents take precedence.
- Existing H-MEM registries retain their original chat scope. New registries use `emberforge-local` and persist that choice for later sessions.
- Previously downloaded packages keep their original filenames and instructions. The frozen-split CLI recognizes both runtime filenames; new exports use the Ember Forge filename.
- Historical screenshots retain the branding visible at capture time. The README labels them accordingly, and the earlier logo preview is named `legacy-brand-preview.jpg`.

The local checkout's physical folder name is independent of the application name. It is left in place so saved workspace paths and running development processes keep their location. Repository clone instructions use the new repository name.
